# Design System

本 skill 负责把 `PROJECT.md`、当前设计要求、相关 PRD 和可读 Figma 归一为根目录 `DESIGN.md`，同时定义框架通用的视觉与响应式基线。组件选择见 `component-usage`，Tailwind / Less 实现见 `css-usage`，页面字段与路由见 `admin-page`。

## 需求到设计

生成可见 UI 前先读取 `PROJECT.md` 和现有 `DESIGN.md`。当文字需求、PRD、Figma 或项目上下文引入稳定设计变化时，先增量更新 `DESIGN.md`，再生成代码。

`DESIGN.md` 记录：

- 与产品目标对应的设计目标、信息密度和视觉性格
- 项目级品牌、颜色倾向、媒体风格和主题策略
- 页面结构、导航表达、列表 / 详情 / 设置等主要体验选择
- 响应式方向、内容优先级和特定范围的设计例外
- 设计来源的适用范围，以及相对本 skill 基线的明确差异

只写已确认且跨页面或后续任务仍有效的结论。未知项继承本 skill，不写占位符；单页像素、临时状态和 CSS 实现细节留在 Figma、任务或代码中。产品事实发生变化时先由 `project-context` 更新 `PROJECT.md`，不能直接在 `DESIGN.md` 改写产品范围。

## 设计依据

视觉决策按当前任务范围使用以下优先级：

1. 完整可读且明确对应目标页面的 Figma
2. 当前任务明确的视觉要求；除非用户明确要求覆盖，否则只补 Figma 未定义的区域与状态
3. `DESIGN.md` 中已确认且适用于当前范围的项目设计规范
4. 项目公共组件的既有视觉契约
5. 同场景现有页面
6. 本 skill 的框架基线

具体 Figma 只覆盖点名页面或组件；未说明的状态、响应式与主题行为继续遵循 `DESIGN.md` 和本 skill。`DESIGN.md` 只描述项目设计结论和差异，不得复制本文件的通用尺度、组件和实现规则。不要为单个业务页建立另一套后台视觉语言。

权威实现来源：

- 颜色与圆角：`src/app/styles/theme-tokens.less`
- 设计颜色 token：`docs/theme/Light.tokens.json`、`docs/theme/Dark.tokens.json`
- Tailwind 映射与断点：`tailwind.config.js`
- 壳层：`src/widgets/admin-shell`
- 列表、详情、设置：`src/widgets/biz-list`、`biz-detail-drawer`、`session-settings`

## 视觉基线

- 面向高频操作的管理后台，保持安静、紧凑、可扫描；不使用营销页式 Hero、装饰性大标题或卡片拼贴。
- 页面背景使用 `color-bg-1`，业务面使用 `color-bg-2`；标准卡片以 `color-border-2` 描边分层，不加阴影。阴影主要留给下拉、Tooltip、Message 等悬浮层。
- 页面区块保持明确间距，不允许筛选、汇总、表格或设置分区边框直接相贴。列表主要区块使用 16px，设置分区和 Drawer 内分组使用 12px。
- 不嵌套装饰性卡片。Card 只用于独立工具面、重复条目、Modal / Drawer 内确实需要描边的内容。
- 主色只表达选中、焦点和主要动作；成功、警告、危险使用对应语义色，普通信息以中性色为主。

## 尺度与层级

沿用 4px 基础网格，优先使用现有高频尺度，避免产生 13px、17px、19px 等近似值：

| 用途 | 基线 |
| --- | --- |
| 紧密图标 / 文案间距 | 4px |
| 同组控件、按钮、行内动作 | 8px |
| 卡片内边距、分区间距 | 12px |
| 页面主要区块间距 | 16px |
| 大组或流程间距 | 24px |
| 普通控件高度 | 32px |
| Drawer 标题栏 | 48px |

圆角层级：小标签或细节 4px；输入、按钮、表格卡片和普通面 8px；大型设置壳、弹层或既有复合面 12px。不要在同一层级随意混用圆角。

字体保持固定尺度，不随视口缩放：

- 辅助信息：12px / 20px
- 正文、表单、表格、操作：14px / 21-22px
- 分区标题：16px / 24px
- 页面标题：20px / 28px

同一信息层级最多使用字号、字重、颜色中的两种差异；避免依赖超大字号制造层级。

## 标准结构

- 列表页使用“筛选 -> 汇总（可选）-> 表格”纵向结构。表格保持紧凑、斑马纹、清晰表头与右侧操作，不转成卡片列表，除非高优先级设计来源明确要求。
- 设置页使用顶部标题与保存动作、左侧锚点、右侧分区内容；分区之间保持 12px，不在一个外层 Card 中继续堆叠无意义 Card。
- 详情保持统一的标题、摘要、Tabs、Descriptions 和记录视觉；业务页不得覆盖公共 Drawer 的背景、Tab、sticky 或滚动结构。
- 空态、加载态、错误态应占据原内容区域，不能因状态切换改变工具栏和页面主要尺寸。

具体组件选择与契约只由 `component-usage` 定义。

## 响应式要求

框架使用 Tailwind 默认断点：`sm 640`、`md 768`、`lg 1024`、`xl 1280`、`2xl 1536`。全局导航已有 900px 的内容精简规则；不要再增加语义相近的任意断点。优先复用公共组件已有 Grid 与响应式行为，缺失时在公共组件集中补齐，不在每个页面各写一套。

PC 页面是信息架构、字段、权限和业务能力的基准。移动端不是桌面页面的等比缩小版，应使用 H5 常见的单列渐进流程：并排区域按任务顺序拆成单面板，侧栏改为遮罩导航，侧边详情改为全屏页面式层级，并提供明确的打开、返回和关闭路径。允许改变展示层级、导航状态和操作承载位置，但不得改变业务语义、权限、必要字段、操作能力与数据顺序。

所有新增或修改页面必须满足：

- 页面在可用内容区内自适应，不出现整页横向滚动、文字重叠、按钮溢出或固定宽度挤压；必要的横向滚动只能留在表格等明确区域内。
- 窄屏可以重排内容、切换单面板层级、改变导航或弹层形态，并隐藏可从当前上下文明确恢复的次要文案；不能删除业务能力或让流程失去连续、明确的返回路径。
- 字体不使用 `vw` / `clamp()` 随视口缩放；控件不得因视口变窄而低于组件既有稳定尺寸。普通控件、工具栏按钮和分页项保持 32px。
- 顶栏和工具栏空间不足时先换行；已有紧凑图标形态时才隐藏次要文字标签，并保留 Tooltip。主操作不能被截断在视口外。

场景规则：

| 场景 | 宽屏 | 窄屏 |
| --- | --- | --- |
| 全局导航 | 固定侧栏，可展开或收起 | `md` 及以下改为顶栏触发的左侧遮罩导航；内容占满视口，选中叶子后关闭导航 |
| 页面多页签 | 顶栏 PageTabs 保留并行任务与快速切换 | `md` 及以下不展示桌面 PageTabs；当前页由顶栏标题定位，页面式层级使用明确返回 / 关闭路径 |
| 筛选 | `md` 起默认每行 4 项 | `sm` 每行 2 项，`xs` 每行 1 项；操作区左对齐并换行 |
| 表格工具栏 | 标题与操作同排 | `md` 以下允许分行；批量条回到文档流，不绝对定位遮挡 |
| 表格 | 按真实内容分配列宽 | 保留字段和操作；内容超宽时表格内部滚动，不把必需列压成 0 |
| 列表行操作 | 外露少量高频动作，其余进入更多菜单 | 操作列只保留一个稳定触控入口；完整动作进入菜单，不删除权限内操作 |
| 设置页 | 左侧 240px 锚点，右侧内容 | `md` 以下锚点改为顶部、横向或可折叠导航，内容占满可用宽度 |
| 主从 / 多面板 | 关联列表与详情可并排或侧边展开 | 一次只展示当前任务面板；进入详情后提供可预期的返回路径并恢复原列表状态 |
| Drawer | 保持侧边上下文和稳定内容宽度 | `md` 以下占满视口并按页面式层级交互；内容独立滚动，Header / Tabs / Footer 不互相遮挡 |
| Modal | 短确认使用场景默认宽度和最大宽度 | 短确认左右至少保留 16px；长表单或连续流程可改为全屏或分步层级，主操作持续可达 |

如果公共组件尚未满足上述窄屏契约，应优先修复该公共组件并验证现有调用方；调用页不要用固定像素 `width` 或深层选择器打补丁。

样式实现、主题变量和 Tailwind / Less 边界只由 `css-usage` 定义。

## 验收

至少在以下视口验证受影响页面：

- 375 x 812：手机窄屏
- 768 x 1024：平板 / `md` 边界
- 1280 x 720：常见后台最小桌面
- 1440 x 900：标准桌面

同时检查浅色 / 暗色、zh-CN / en-US、最长文案、空态、加载态、弹层和 Drawer 打开态。确认：

- 区块间距、背景、描边、圆角和文字层级一致。
- 无重叠、整页横向滚动或不可达操作。
- Sticky 元素粘在真实滚动容器中，不遮挡正文。
- 表格列宽、内部滚动和固定操作列在窄屏仍可用。
- 响应式修复位于正确公共层级，没有业务页重复补丁。
- 视觉结果符合 `PROJECT.md` 的产品目标和 `DESIGN.md` 的项目设计规范，没有把未确认的视觉推断扩散为全局风格。
